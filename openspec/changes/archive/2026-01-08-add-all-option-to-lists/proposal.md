# 变更：新增获取资源名称列表的 API

## 为什么 (Why)
前端在创建资源（如创建容灾实例）时，需要从下拉框中选择关联资源（集群、存储、备份策略）。现有的列表 API 返回了完整的资源详情且默认分页，这对于仅需要列表进行选择的场景来说（1）数据量过大，浪费带宽；（2）包含分页逻辑，不能一次性展示所有选项；（3）如果为了获取全部数据而在此接口增加 `limit=-1` 逻辑，会返回大量无用详情数据。
因此，我们需要一组轻量级 API，仅返回资源的名称列表（可能包含最基本的元数据，如 ID/UID），用于前端选择器。

## 变更内容 (What Changes)
- **新增 API 路由**:
  - `GET /disaster/v1/clusters/names` -> 返回所有集群名称列表
  - `GET /disaster/v1/storages/names` -> 返回所有存储名称列表
  - `GET /disaster/v1/policies/names` -> 返回所有策略名称列表

- **实现详情**:
  - 每个 API 依然会调用 Lister 获取所有资源（走 Informer 缓存，性能无虞）。
  - 对结果进行映射，仅提取 Name 字段（以及可能的 UID 或 Namespace，视资源类型而定）。
  - 返回结构简化，不再使用标准的 `CollectionData` 分页结构，而是直接返回字符串数组或简单的对象数组。例如 `["cluster-a", "cluster-b"]` 或 `[{"name": "cluster-a"}, ...]`。为了保持扩展性，建议返回对象数组 `[{name: "xxx"}]`。

## 影响 (Impact)
- **新增功能**: 不影响现有 API。
- **前端优化**: 大幅减少网络传输载荷，加快表单页面加载速度。
